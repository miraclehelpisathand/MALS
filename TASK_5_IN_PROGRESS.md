## Implemented locally

- Immutable template/settings and certificate snapshots; expiry dates; revocation on reopening; administrator or authorised trainer/leader reissue; administrator historical-date verification with audit record. Published settings from the same family can be used to certify an older recognised completion without changing its assigned version. Template upload and settings save are atomic.
- Independent refresher assignments, reading progress, assessment attempts/limits, reviews and completion events. Original records are backfilled to their assignment without resetting history. Group/individual access is inherited from the original assignment; standard assignments retain their original uniqueness. Cycle write and review actions lock the qualification before the cycle.
- Local scheduler function, callable only by the database owner, selects the latest published refresher version, targets the expiry date, avoids duplicate scheduling and records non-personal heartbeat/error information. A restricted monitor RPC, opt-in GitHub Actions check and operations draft have been added locally; they have not been deployed or configured. Completing a same- or different-course refresher renews the original qualification. A revoked original qualification invalidates its outstanding refresher. **No cron job or external alerting is installed.**
- Feature-flagged authoring, cycle selection, scoped certificate/refresher views, PDF download, approval and historical verification screens, with an administrator scheduler-health panel. The author’s PDF is flattened in the browser to a bounded PNG; only that image is stored, not the original PDF. PDF downloads embed the image and do not carry PDF actions or annotations. SQL independently restricts PNG structure and dimensions; this reduces PDF-specific risks but does not guarantee safety from image-decoder defects. Māori macrons are covered by the included DejaVu Sans font; unsupported glyphs fail explicitly instead of silently corrupting names.
- The user selected hosted Healthchecks.io for independent missed-heartbeat alerts. The user also reports creating a dedicated Supabase monitor account and adding the monitor email/password as GitHub secrets. - The user confirmed in-app download at completion rather than automatic email: an issue record is created at completion and the learner can generate a PDF for download and printing whenever needed.
- PGlite tests exercise pre/post-migration compatibility, independent reading/assessment/review, historical backfill, group archive/restore and individual access, scheduler idempotency and renewal. ## Local concurrency validation

Temporary PostgreSQL 17.11 (matching the development major/minor version) and PostgreSQL 18 instances passed two real multi-connection race tests: reopening first makes a waiting refresher write fail closed; refresher renewal first is subsequently revoked when the original course reopens. An overlapping scheduler skips a locked qualification and creates its cycle on retry. This does not replace testing on the target Supabase PostgreSQL version or through signed-in HTTP APIs.

The reproducible script is `scripts/task5-postgres-race.mjs`. Install `embedded-postgres` and its `pg` dependency **outside the repository**, then set `TASK5_PG_NODE_MODULES` to that external `node_modules` directory and run `node scripts/task5-postgres-race.mjs`. It creates and destroys a temporary local cluster on port 55432 (override with `TASK5_PG_PORT`).

## Fictional certificate browser check

`scripts/task5-browser-certificate.mjs` generates a synthetic single-page PDF and uses the actual editor and PDF renderer, without connecting to Supabase. It tested the editor's number inputs and pointer dragging, all five text fields and their positions in the generated PDF, the corners of the flattened artwork, removal of PDF actions/annotations, and the resulting PNG against the local PGlite database validator. It passed for cropped/offset templates at 0°, 90°, 180° and 270° and browser viewport widths of 320, 390 and 1280 pixels. During this check, dragging revealed that arbitrary coordinates did not match the form's half-percent input step and could block saving; dragging now rounds to that step. These checks do not establish accessibility, actual printer output, real Supabase permissions or safety against malformed files.

To reproduce, install `playwright-core@1.64.1` and `@sparticuz/chromium@153.0.0` **outside the repository**; install the regular project dependencies with `npm ci`. Start a separate Vite server with `npm run dev -- --port 5174 --strictPort --config scripts/task5-vite.config.mjs`, then run `TASK5_BROWSER_NODE_MODULES=/path/to/external/node_modules node scripts/task5-browser-certificate.mjs`. `TASK5_PREVIEW_URL` can override the default `http://127.0.0.1:5174`. Chromium needs its normal system libraries; on the validation sandbox, additional NSS libraries and `LD_LIBRARY_PATH` were needed. The isolated Vite cache avoids interfering with the normal port 5173 preview. The script creates temporary harness files in the repository root and removes them on normal completion or failure.
